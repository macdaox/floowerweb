# EVERSTEM 一体化内容编辑器设计

## 目标

将当前“先到媒体库上传，再回内容编辑器选择图片”的后台流程，改造成运营人员可在一个编辑页面内完成全部工作的体验。产品、案例、文章和普通页面统一采用结构化字段与可视化富文本相结合的编辑方式。

成功标准：运营人员无需离开当前编辑页面，即可编辑文字、上传图片、设置封面、维护图库、预览并保存或发布内容；独立媒体库继续保留，作为复用和集中管理入口，而不是必经步骤。

## 用户体验

### 统一编辑页面

每种内容的编辑页由以下区域组成：

1. 基本信息：标题、别名、分类、摘要、状态等现有结构化字段。
2. 正文：基于 TipTap 的可视化富文本编辑器。
3. 图片：封面与图库直接上传、选择已有图片、预览、排序、移除和设为封面。
4. SEO 与发布：SEO 标题、描述、发布检查、预览、保存草稿和发布操作。

产品继续保留产品编码、分类和规格参数；案例继续保留地点与分类；文章继续保留作者和发布时间；普通页面继续保留页面标识与模块化内容能力。

### 富文本能力

首版仅提供运营所需的稳定能力：

- 段落与二、三级标题
- 加粗、斜体和链接
- 有序与无序列表
- 引用
- 撤销与重做
- 粘贴纯文本或经过清理的富文本
- 点击、拖放或粘贴上传图片
- 图片替代文本与说明文字

不加入任意字体、字号、颜色、脚本、iframe 或自由 HTML，避免破坏前台视觉和安全边界。

### 图片工作流

编辑器中的上传操作复用现有媒体上传 API 和 R2 存储规则。上传成功后，图片立即进入当前正文、封面或图库，同时也进入媒体库，供其他内容复用。

图片上传期间显示进度与失败重试。尚未成功上传的图片不能保存为内容引用。移出当前内容只解除引用，不自动删除 R2 对象；物理删除仍由媒体库完成，并继续执行引用保护。

封面和图库采用缩略图卡片：支持拖动排序、设置封面、编辑英文替代文本和移除。用户也可以从同一页面打开“选择已有图片”弹窗，但无需跳转到媒体库页面。

## 技术设计

### 编辑器组件

新增共享的 `RichTextEditor`，由产品、案例、文章和页面编辑器调用。组件封装 TipTap 初始化、工具栏、HTML/JSON 转换、图片上传、脏状态提示和销毁生命周期。

现有 `editor.ts` 继续负责各实体的结构化字段与保存流程；富文本和图片区域拆成独立组件，避免继续扩大单个编辑器文件。

### 内容格式

富文本在客户端使用 TipTap 文档 JSON 编辑，提交 API 时转换为受限、规范化的 HTML 字符串，继续存入现有正文文本字段。服务端对 HTML 进行白名单清理，只允许设计规定的标签、属性和本站媒体 URL。这样无需迁移现有正文列，也能保持前台 SSR 输出简单稳定。

普通页面现有 `sections_json` 继续作为页面结构来源；文本型区块增加受限富文本内容，图片型区块复用统一媒体引用。已有数据在读取时兼容，保存后转换为新格式。

### 媒体接口

复用 `/api/admin/media` 上传接口、R2 魔数校验、文件大小限制和媒体索引。上传接口返回的媒体对象直接供富文本、封面和图库使用。

服务端保存内容时验证所有媒体 ID 均存在、未删除且属于当前 D1/R2 环境；发布时要求封面及正文关键图片具备英文替代文本。正文中的媒体引用纳入现有引用保护，避免媒体仍被文章使用时遭到物理删除。

### 前台渲染

新增统一的安全富文本渲染组件，负责输出清理后的内容和响应式图片。前台英文站保持现有视觉规范，不允许后台编辑器写入任意内联样式。

## 状态、错误与并发

- 上传、保存和发布分别显示明确状态，上传失败不丢失已填写文字。
- 页面存在未保存修改时，关闭或切换内容会提示确认。
- 沿用现有 `updatedAt` 乐观锁；发生冲突时提示重新加载，不静默覆盖他人修改。
- 保存草稿允许部分内容；发布继续执行完整字段、SEO、图片和替代文本校验。
- 编辑器错误以中文显示，API 保持结构化错误码和字段错误。

## 安全与性能

- 服务端对富文本执行严格白名单清理，拒绝脚本、事件属性、危险 URL 和外部 iframe。
- 上传继续验证真实文件签名、MIME、扩展名和大小。
- 编辑器代码只加载在中文后台，不增加公开网站的 JavaScript 体积。
- 正文图片使用现有媒体路由、明确尺寸与延迟加载；首图按前台现有性能策略处理。

## 测试与验收

- 单元测试：富文本规范化、白名单清理、危险链接拒绝、媒体引用提取。
- 集成测试：直接上传并保存正文图片、图库排序、封面设置、引用保护、并发冲突和发布校验。
- 浏览器测试：产品、案例、文章和普通页面各完成一次创建、上传、编辑、预览和发布流程。
- 回归测试：现有纯文本内容仍能读取和编辑；媒体库独立使用方式保持可用；公开页面无后台编辑器代码。

验收时，运营人员应能在单个编辑页面完成一条内容从草稿到发布的全过程，不需要先访问媒体库。

## 发布与兼容

先实现共享编辑器与服务端清理，再逐一接入文章、产品、案例和普通页面。所有实体接入并通过测试后一次发布，避免线上同时存在不一致的编辑体验。

现有正文和媒体数据不做破坏性迁移。新编辑器必须能加载旧内容；新保存的数据保持前台兼容。若编辑器资源加载失败，结构化字段仍可读取，但禁止提交可能丢失正文的保存操作。
